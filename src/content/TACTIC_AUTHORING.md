# 战术内容标准

这个应用的核心是让青少年在比赛中认出信号、做出选择，并看懂球路。每个新增战术只讲一个明确结果；每个组合只连接 2–3 个有条件的选择，不写成必须完成的固定套路。

## 新增单项战术

在 `next.ts` 同时加入 `nextTactics` 和同 ID 的 `nextGuides`。可参考 `expansion.ts` 中的网前专题。

每个单项必须包含：

- `goal`：这一招想改变什么，例如压缩角度、争取回位时间或逼出低球。
- `when`：可在比赛中看见的使用信号，包括来球、自己的平衡与对手站位。
- `cue`：一条能在场上快速想起的短句。
- `mistake`：青少年最容易犯的一个选择错误。
- `why`、`recognize`、`avoid`：说明原理、辨认信号和需要放弃或调整的情况。
- `decisions`：固定三步，依次写“先判断什么”“怎么执行”“下一拍看什么”。
- `practice`：有同伴、次数、变化条件和观察重点的可执行练习。

动画长度为 5–20 秒，至少 3 帧。第一帧先呈现比赛信号，中间帧对应判断与执行，最后一帧回到“继续准备下一拍”的状态。时间从 `0` 递增到 `1`；球员和球的位置使用 `0–1` 的场地坐标。字幕要写选择，不写“必然得分”。

## 新增组合打法

在 `nextCombinations` 加入 2–3 个阶段，并为每组准备至少 2 种应变。

- `cue` 写当前先执行什么。
- `transition` 写看到什么信号才进入下一招；条件不成立时也要说明如何继续。
- `trigger` 写对手或来球发生了什么变化。
- `response` 写对应调整与打完后的准备。
- `excerpt` 可只播放基础战术中与该阶段有关的帧，并改写开头、结尾或三条当前判断。

同一个单项可以出现在多组组合中，但组合必须解释新的前后关系，不能只重复单项名称。

## 发布前检查

运行 `npm run check:content`。检查会阻止缺少讲解、坐标越界、时间顺序错误、组合引用不存在、应变不足或转换信号过短的内容进入正式版本。随后运行完整构建，并在 iPhone 与 Pixel 10 视图检查卡片、字幕、当前判断、组合路径和应变展开状态。
